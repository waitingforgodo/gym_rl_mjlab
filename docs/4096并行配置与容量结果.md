# 4096 并行配置与容量结果

当前 RTX 5070 Laptop（8151 MiB 显存）已对 AMP、BeyondMimic 完整状态和无状态估计任务分别执行 **4096 环境、30 次更新**的串行容量短测。三项均正常结束、计时有效，并满足至少 1 GiB 剩余显存和 2 GiB WSL 可用内存的门槛。

| 任务 | 中位吞吐（步/秒） | 最低剩余显存（MiB） | 最低 WSL 可用内存（GiB） |
| --- | ---: | ---: | ---: |
| AMP 舞蹈 | 88777 | 5644 | 8.12 |
| BeyondMimic 完整状态 | 76622 | 5916 | 7.92 |
| BeyondMimic 无状态估计 | 76382 | 5924 | 7.89 |

这些结果证明当前机器能以 4096 环境完成短时采样和更新，不证明策略收敛、长期温度稳定或桌面始终流畅。容量测试模型仅位于本地 `outputs/benchmarks/runs/`，不会被正式训练的 `latest` 选中。

## 当前正式 profile

| 任务 | 默认 profile | 每轮样本数 |
| --- | --- | ---: |
| 平地速度基线 | `velocity_flat_4096` | 98304 |
| 平地鲁棒候选 | `velocity_robust_4096` | 98304 |
| BeyondMimic 基线 | `tracking_4096` | 98304 |
| BeyondMimic 完整状态候选 | `tracking_robust_4096` | 98304 |
| BeyondMimic 无状态候选 | `tracking_no_state_estimation_robust_4096` | 98304 |
| AMP 舞蹈 | `amp_dance_4096` | 98304 |

每个环境仍采样 24 步，PPO 仍分 4 个 minibatch，所以每个 minibatch 为 24576 条。环境数变化会同时改变每轮数据量和优化行为，不能仅理解为仿真加速。

AMP 的 4096 profile 保留实际容量短测使用的判别器配置：batch 4096、每 PPO 轮更新 8 次、回放容量 400000。它没有暗中引入未经测试的更大判别器批量。由于 PPO rollout 比 2048 版本翻倍，判别采样占比和回放覆盖轮数会减半，正式训练仍应结合 TensorBoard 的判别准确率、风格奖励和存活情况判断。

## 兼容策略

重复的 2048 profile 已按要求删除。新运行会把完整 `profile_spec` 和原始哈希嵌入清单，因此不再要求永久保留同名 JSON；已有包含快照的模型仍可回放、导出和续训。所有从零训练快捷脚本均使用 4096 profile。

一次性的后台等待/排队验证程序已经删除。以后需要重新测容量时，使用长期保留的通用入口：

```bash
bash scripts/01_benchmark.sh --profile amp_dance_4096 --envs 2048 4096 --iterations 30
```

不同任务必须分别测试；上面的 AMP 结果不能直接替代新动作、新模型或新硬件的容量检查。

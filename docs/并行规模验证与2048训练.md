# AMP / BeyondMimic 的 2048 并行配置与训练记录

当前机器上，AMP 舞蹈、BeyondMimic 完整状态和无状态估计任务均已通过 **2048 个并行环境**的容量检查，和速度任务的快捷脚本并行数一致。测试硬件为 RTX 5070 Laptop（8151 MiB 显存），运行时为 mjlab 1.6.0 / RSL-RL 5.4.2。

本次按 2048 这个目标验证，没有测试更高档位，因此 2048 是已验证档位，不是硬件最大值。短训不证明长时间温度、桌面响应性或舞蹈收敛。

## 1. 如何验证容量

所有任务串行使用 GPU，每个任务单独创建环境和训练进程，前五次更新不参与吞吐统计。资源监测覆盖初始化与训练，GPU 余量统计整块显卡、内存统计整个 WSL，每秒采样可能漏掉瞬时峰值。

先用原学习配置进行容量扫描，各档训练 30 次更新：

| 配置 / 档位 | 环境数 | 中位吞吐（步/秒） | 最低剩余显存（MiB） |
| --- | ---: | ---: | ---: |
| AMP 原学习配置 | 512 | 23196 | 6946 |
| AMP 原学习配置 | 1024 | 41438 | 6746 |
| AMP 原学习配置 | 2048 | 63191 | 6406 |
| BeyondMimic 完整状态 | 512 | 16954 | 6948 |
| BeyondMimic 完整状态 | 1024 | 31693 | 6736 |
| BeyondMimic 完整状态 | 2048 | 52192 | 6390 |
| BeyondMimic 无状态估计 | 2048 | 51338 | 6390 |

各档均 `status=passed`、`timing_valid=true`。无状态估计版本在完整状态逐档检查后，单独验证 2048。此表的 AMP 仍使用原判别器学习设置；新默认 AMP 放大了判别器采样和回放，实际结果单列于第 4 节，不能将两个实验混为一项提速对照。

## 2. 修改了哪些默认值

为保留已有模型的 profile 字节哈希，原 256 profile 不改写；新增独立配置：

| 当前快捷入口 | 当前默认 profile | 默认并行 / 预算 | 旧配置 |
| --- | --- | --- | --- |
| [18_train_amp_dance.sh](../scripts/18_train_amp_dance.sh) | [amp_dance_2048](../profiles/amp_dance_2048.json) | 2048 / 30000 更新 | `amp_dance` 保留 256 |
| [16_train_tracking_robust.sh](../scripts/16_train_tracking_robust.sh) | [tracking_robust_2048](../profiles/tracking_robust_2048.json) | 2048 / 30000 更新 | `tracking_robust` 保留 256 |
| 16 号脚本加 `--profile tracking_no_state_estimation_robust_2048` | [tracking_no_state_estimation_robust_2048](../profiles/tracking_no_state_estimation_robust_2048.json) | 2048 / 30000 更新 | `tracking_no_state_estimation_robust` 保留 256 |

## 3. 采样量与 AMP 的配套调整

每个环境每轮采样 24 步，PPO 使用 4 个 minibatch：

| 项目 | 原 256 环境 | 新 2048 环境 |
| --- | ---: | ---: |
| 每轮状态转移 | 6144 | 49152 |
| PPO 每个 minibatch | 1536 | 12288 |
| AMP 判别器 batch | 1024 | 4096 |
| AMP 判别器每轮更新次数 | 4 | 8 |
| AMP 判别器每轮每类采样总量 | 4096 | 32768 |
| AMP 历史回放池容量 | 50000 | 400000 |

AMP 的 rollout 增大 8 倍，因此判别器每轮采样量和回放容量也增大 8 倍，保持采样比例和约 8.14 轮的历史。回放原始 float32 数据约 253.3 MiB，模型保存也会包含有效回放数据。学习率、奖励定义、G1 物理/PD、动作尺度、观测和策略周期保持不变。

这些是维持学习比例的工程起点，不能证明与小批量优化完全等价或舞蹈效果更好。仅覆盖 `--envs` 不会自动更改判别器，缩回旧 256 档时可显式使用 `--profile amp_dance --envs 256`。

相同更新次数下，2048 环境比 256 环境产生 8 倍样本。原 256×30000 更新与 2048×3750 更新的总样本量相同；直接保留 30000 更新是增加训练采样预算，不能把吞吐提升解释为同质量收敛时间缩短。

## 4. 新默认脚本的实际训练

三种新默认配置各完成 **100 次更新、2048 环境、4915200 条采样转移**，均保存 `model_99.pt`。所有曲线标量和最终 actor/critic 参数为有限值，计时有效；49 项 CPU 测试通过。

| 实训配置 | 中位吞吐（步/秒） | 最低剩余显存（MiB） | 最低 WSL 可用内存（GiB） |
| --- | ---: | ---: | ---: |
| `amp_dance_2048` | 65719 | 6134 | 6.78 |
| `tracking_robust_2048` | 56775 | 6382 | 7.61 |
| `tracking_no_state_estimation_robust_2048` | 56802 | 6384 | 6.66 |

新 AMP 模型包含 400000 条有效历史转移，判别器优化器累计 800 步，回放指针为 115200。三种模型均保存公共控制步 2400，更新编号 99；这些状态已从实际 checkpoint 读取核对。

模型保存在正式运行目录，均为新建实验，未覆盖原速度或 256 档模型：

```bash
AMP_RUN="/home/godot/g1-mjlab-workspace/outputs/runs/20261026_180610_030444_amp_dance_2048_amp_dance_2048_validation100"
BEYONDMIMIC_RUN="/home/godot/g1-mjlab-workspace/outputs/runs/20261026_180747_437789_tracking_robust_2048_tracking_robust_2048_validation100"
BEYONDMIMIC_NO_STATE_RUN="/home/godot/g1-mjlab-workspace/outputs/runs/20261026_180943_537991_tracking_no_state_estimation_robust_2048_tracking_no_state_estimation_robust_2048_validation100"
```

每个目录内的 `model_99.pt` 可用于回放、评估或续训。汇总位于本机 `outputs/checks/20261026_parallel_2048_validation.json`，对应终端日志为 `outputs/checks/20261026_parallel_2048_training.log`，各任务单独的日志路径也保存在汇总中。

本次完成的是扩大并行规模后的实训验证，未把默认 30000 更新预算全部跑完；100 更新不代表舞蹈收敛。没有进行新模型的长时间失败率、动作质量或真机验收。

## 5. 继续训练、回放与曲线

三种任务分别训练，单 GPU 依次执行：

```bash
# AMP：默认约 10 秒的 AMP 舞蹈数据
bash scripts/18_train_amp_dance.sh

# BeyondMimic：默认 dance_102 参考轨迹，完整状态
bash scripts/16_train_tracking_robust.sh

# BeyondMimic：去掉指定状态估计观测的独立版本
bash scripts/16_train_tracking_robust.sh \
  --profile tracking_no_state_estimation_robust_2048
```

上述默认预算均为本次新增 30000 更新。从第 4 节已经完成的 100 更新模型继续达到总计 30000 更新，使用对应运行目录并新增 29900：

```bash
RUN_DIR="替换为第4节对应任务的实际运行目录"
bash scripts/03_resume.sh --checkpoint "$RUN_DIR" --iterations 29900

# 回放同一个模型；打开终端打印的网页地址
bash scripts/04_play.sh --checkpoint "$RUN_DIR"

# 另开终端查看训练曲线
bash scripts/07_tensorboard.sh
```

三个任务同时存在时，请明确指定运行目录或模型文件；`latest` 选择最近正式训练，不按任务筛选或按质量排名。AMP 与 BeyondMimic 的奖励定义、默认专家数据不同，不用总回报横向判断谁更好。

AMP 的算法、数据与部署流程见 [AMP 舞蹈训练与仿真部署](AMP舞蹈训练与仿真部署.md)，实验来源见 [训练配置优化依据与对照实验](训练配置优化依据与对照实验.md)。

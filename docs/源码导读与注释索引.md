# 源码导读与注释索引

新的行走/动作模仿候选重点阅读 `workspace/configuration.py`、`workspace/recipes.py` 和 `profiles/*_robust.json`。公开配置对照、参数解释及实验步骤见 [训练配置优化依据与对照实验](训练配置优化依据与对照实验.md)。

本次中文注释覆盖自建工作空间的生产代码、快捷脚本与测试说明。第三方 mjlab/RSL-RL 的源码副本已放入 [third_party/](../third_party/README.md)，可直接在 IDE 中阅读；安装目录保持原样，训练仍导入原虚拟环境中的依赖。

先读 `训练流程与配置详解.md` 理解训练对象与计数，再从 `scripts/03_resume.sh → g1.sh → workspace/cli.py → workspace/runtime.py` 顺序看代码。profile 的 JSON 不插入注释字段，因为字节哈希参与旧模型续训校验，说明集中写在 Markdown。

## 1. scripts：可复制、可覆盖的操作入口

`common.sh` 统一找到安装根目录并检查标记，设置两个默认值：平地并行数 2048、checkpoint=latest。每个编号脚本只做一件事，具体参数放在源码开头的中文注释中。

它们使用 `"$@"` 转发参数，而不是 eval 或把整串命令拼成字符串。默认参数在前，用户补充参数在后，argparse 会采用最后一个同名标量参数；因此 `03_resume.sh --iterations 2000` 能覆盖默认 1000。

`07_tensorboard.sh` 是例外：它直接用 `.runtime-path` 中的解释器启动 TensorBoard，隐藏 GPU，并降低 CPU 优先级。不经过训练入口，不加载策略。

## 2. g1.sh / setup.sh / apply_update.sh

`g1.sh` 只负责进程环境：固定解释器、隔离缓存、清理外部 Python 路径、设置线程与优先级，然后 exec Python CLI。它在子进程中运行，不把这些变量写入用户 shell 配置。

`setup.sh` 只做首次安装，已存在目标目录时拒绝覆盖。运行目录、数据、cache 都放在 Linux 文件系统，而不是在 Windows 挂载盘训练。

`apply_update.sh` 对受管理源码/脚本/文档先做语法检查，取本空间训练锁，再备份和同步，最后运行 CPU 测试。它保留 profiles、outputs、motions、.runtime-path 和已安装依赖。不在更新时自动训练或做 GPU 验收。

备份目录包括被替换的原文件；新文件名另写 new-files.txt。更新期间若本空间已有训练/benchmark 持锁，会提示等结束再运行。这个锁不会阻止用户在其他目录启动任务，因此也不能作为全机资源管理器。

## 3. cli.py：参数、路径与资源生命周期

`parser()` 定义所有子命令。训练与续训有 envs/iterations/name/seed；推理有 checkpoint；evaluate 才允许 `--velocity-cmd VX VY WZ`。参数帮助可用 `bash ~/g1-mjlab-workspace/g1.sh evaluate --help` 查看。

`resolve()` 只对旧 g1_continue 做特殊路径解析；普通 latest/目录/模型文件交给 contract。路径解析不会按文件系统修改时间猜“最好模型”。

`doctor()` 读取包版本与资源，不创建仿真；`self_check()` 创建 4 环境，走 32 步零动作，检查有限值，不优化网络。

`benchmark()` 为每一档建立独立子进程，保存 stdout/stderr，使用 perf_counter/monotonic 的间隔计时，收集 TensorBoard 与资源结果。子进程用内部 benchmark-run 标志写到独立模型目录并避免重复抢父锁。

`main()` 是分发器。推理路径的 env 都在 finally 中关闭，避免正常错误路径泄漏 GPU 环境。`show-config` 读取原始 YAML 文本，不创建模型，也不执行 Python YAML 标签。

## 4. runtime.py：与官方训练框架的边界

`initialize()` 核对 mjlab=1.6.0、rsl-rl-lib=5.4.2，设置 Warp kernel 缓存、CPU 线程并注册任务。它不安装/升级依赖。

`build_configs()` 加载官方 train/play 配置副本，应用 profile 的少量 agent_overrides 与 CLI 环境数/种子。对 tracking 检查动作名字顺序、频率和数组形状。返回 spec、env_cfg、agent_cfg、manifest 四个对象。

`checkpoint_context()` 优先恢复模型对应的 profile 与动作路径。没有运行清单的旧模型只允许显式 legacy-velocity 假设，并不能证明全部旧配置一致。

`make_env_runner()` 创建 `ManagerBasedRlEnv` 与 `RslRlVecEnvWrapper`，从 registry 选择任务专属 runner。tracking runner 的 ONNX 导出包含参考动作，不应替换成只导出普通 Actor 的通用 runner。

`train()` 在构造 runner 前保存完整参数快照，因为 runner 会修改传入字典。resume 全量恢复模型和优化器，校正更新编号后调用 learn。finally 中 flush/close TensorBoard、关闭 env、保存资源记录。

`load_for_inference()` 使用 play 配置、只加载 Actor、切换 eval 模式；固定速度在配置副本中应用，记录评估条件。归一化统计跟随 checkpoint，不用当前评估数据重新学习一套归一化。

`view()` 管理本机 Viser/native viewer；`evaluate()` 实施固定仿真时长测试，累计真实终止与 RMSE。

`export_bundle()` 先采样真实观测对照训练策略与 JIT，再导出 ONNX、接口清单、哈希与禁用的硬件模板。`deploy_sim()` 不创建 PPO runner，只加载导出 JIT 和环境，验证导出后闭环接口。

## 5. contract.py：避免无声错配

`latest_checkpoint()` 用正则只接受 model_数字.pt 并按整数排序。

`joint_permutation(source,target)` 要求两个名字列表都无重复且集合相同，返回目标每一项在源数组的下标。例如 source=[a,b,c]、target=[c,a,b]，结果为 [2,0,1]。这种检查比只判断长度可靠。

`validate_resume()` 对比任务、profile 哈希、动作哈希、库版本和控制周期。命令行改环境数允许，但编辑 profile 文件会改变哈希。它不是完整物理状态的序列化验证器，也不能为 legacy 模型恢复丢失的实验历史。

`choose_parallelism()` 只选成功且 timing_valid 的行，还要求显存/内存余量；吞吐接近最佳时选较小档，避免少量加速带来额外资源需求。

## 6. evaluation.py：这次新增的统计协议

`configure_fixed_velocity()` 同时修改 ranges 并关闭 heading、standing、world-frame、forward-only 与初始速度注入。只改 ranges 不够：官方命令器会通过其他分支再次改变目标。heading_command=False 还要求 ranges.heading=None，否则官方构造器会报错。

`velocity_protocol()` 保存真正使用的范围、随机分支、命令坐标系和重采样周期。两模型比较时，除 checkpoint 外应尽量保持这些字段、seed、环境数与评估时长一致。

`survival_statistics()` 用每个环境的失败次数统计不同概念：总事件数、发生过失败的环境数、观察时窗内完全无失败比例及每环境分钟的事件频率。它不把 5 次事件直接解释为 5 个失败环境。

`is_direct_metric()` 排除 Episode_* 复位日志。play 的超长回合使 Episode_Reward 的分母很大，而且缓存日志会被多次读取；所以本工具单独累计失败和误差，不把这些快照再平均成验收指标。

## 7. motion.py：数据转换与四元数

`normalize_quat()` 要求有效非零四元数并归一化。`continuous_quat()` 沿时间轴统一符号，因为 q 和 -q 表示同一姿态，但直接差分会造成虚假突跳。

`resample_csv()` 先把 CSV 根四元数 xyzw 重排成 wxyz。位置和关节角按时间做线性插值，姿态做最短弧 SLERP，接近同姿态时使用线性插值后归一化的极限分支。真实时间不变，不是简单每隔几帧抽样。

`angular_velocity_world()` 先计算 `q_next * inverse(q_prev)`，转成旋转向量再除 dt。该乘法顺序给出世界系增量，反过来则是不同的坐标系含义。小角度用极限避免除零，中间帧平均前后增量，端点用单边估计。

`prepare()` 根据当前模型名字把 SDK 列顺序映射到 MuJoCo qpos 地址，逐帧调用 mj_forward，收集全刚体世界位姿，计算速度。它只做运动学，不解接触动态可行性。`inspect()` 在训练前再次检查键、名字、形状、频率、有限值和四元数长度。

## 8. telemetry.py / timing.py

ResourceSampler 在后台约每秒采集 GPU 总空闲与 WSL MemAvailable。GPU 初始化前开始，finally 中停止；异常/无输出用 None，不伪造可用资源。

`timing_statistics()` 按 PPO step 关联 fps/collection_time/learning_time，跳过前 5 条预热，检查缺项、负耗时与非有限值。一个负值也会使 timing_valid=false，不让正中位数掩盖错误。

`monotonic_runner_clock()` 仅临时替换当前进程 runner 模块里的 time 引用，用 perf_counter 计算间隔。不会修改标准库 time.time，所以 event 的 wall time 仍正确。异常退出同样恢复模块引用；该工作空间每个进程只设计一个 learner。

## 9. tests：回归测试证明什么

测试按功能分组：test_contracts 检查文件选择、关节映射、兼容性与并行选择；test_motion 检查时间/四元数/坐标系/NPZ；test_timing 检查时钟回拨与异常计时；test_evaluation 检查固定命令和事件/环境数区分。

基础协议/数据测试不需要 GPU，可在满足其轻量依赖的工具 Python 上执行。新增 `test_recipes` 需要固定 mjlab/Torch 运行时，但只在 CPU 检查配置，未安装 mjlab 时会跳过。这些检查不能替代实际仿真、收敛、导出和长期运行验证。快捷脚本在 Ubuntu 更新时还会做 Bash 语法检查。

## 11. configuration.py / recipes.py：新候选的显式配置

`apply_agent_overrides()` 解析点号路径，既支持 dataclass 字段，也支持 `actor.distribution_cfg.std_type` 这样的字典字段；未知字段、错误类型和非有限数值会提前报错。`validate_ppo_config()` 检查正数、概率范围、网络维数及采样批量是否能整除 minibatch 数，避免无效配置进入优化。

`inherited_run_options()` 在用户没有显式传入时继承 checkpoint 清单中的环境数和种子，从零训练使用 profile/42。`scripts/03_resume.sh` 已同步取消强制 2048，显式的命令行参数或 `G1_ENV_COUNT` 仍可覆盖。

`apply_recipe()` 只在新 profile 声明 recipe 时生效。行走配方复用官方课程函数，新增失败、髋/膝驱动力矩与关节加速度代价；跟踪配方明确 train=adaptive、play=start。函数与每个系数的中文注释都在 `recipes.py`，物理参数、PD 和观测接口保留原任务定义。

清单同时保存 profile 哈希、配方源码哈希、生效 agent 哈希与每轮样本量。新配方加载后会 reset 一次环境，使官方 runner 恢复的公共步计数立即决定课程阶段。旧模型没有 recipe 时仍走原兼容契约。

`scripts/tools/compare_policies.py` 串行比较相同任务与动作的策略，统一评估种子和协议，保存失败统计与物理 RMSE，不使用不同奖励定义的总回报自动排名。`tests/test_configuration.py`、`test_recipes.py` 覆盖参数覆盖、续训兼容和课程阈值；配置集成测试使用固定依赖但不创建 GPU 环境。

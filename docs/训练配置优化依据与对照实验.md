# G1 训练配置优化依据与对照实验

本文保留最初 256/2048 环境候选的设计依据；当前脚本已切换到独立的 4096 配置，重复的 2048 源 profile 已删除。当前容量结果见 [4096 并行配置与容量结果](4096并行配置与容量结果.md)，历史实测数字仍作为对照记录保留。

本文对应 2026-10-26 的代码修改、mjlab 1.6.0、RSL-RL 5.4.2 和 RTX 5070 Laptop 8 GiB。覆盖平地行走、训练效率与动作模仿三个目标。新配置是研究候选；是否更稳定、是否更快达到同一质量目标，需要对照实验确认。

## 1. 先明确“业界最优”的边界

目前不存在一份能跨仿真器、机器人驱动、观测、奖励、任务和硬件都保持最优的 JSON。公开项目采用不同算法和评估条件，不能只比较训练分钟数。

本次优先使用公开、可复现且能直接适配当前固定依赖的 PPO 实现。研究还包括 FastSAC/FastTD3 等 off-policy 路线：[Learning Sim-to-Real Humanoid Locomotion in 15 Minutes](https://arxiv.org/abs/2512.01996) 在论文所述硬件和任务条件下展示了快速训练。它使用不同的算法、缓存和更新组织；本项目没有把相关超参数直接混进 PPO，也没有据此承诺本机 15 分钟收敛。

原来的四个 profile 保持原样，已有 checkpoint 与训练目录保留。新实验使用独立 profile、源码配方与运行目录；当前已经启动的旧训练进程也不会被新文件自动切换。

## 3. 新文件与参数覆盖顺序

| 文件 | 作用 |
| --- | --- |
| `workspace/common/configuration.py` | 严格覆盖 dataclass/字典参数、检查采样批量与优化参数、计算生效学习参数哈希 |
| `workspace/common/recipes.py` | 中文注释的环境配方：速度课程、三个下肢/失败代价、动作自适应采样 |
| `workspace/velocity/profiles/velocity_robust_4096.json` | 4096 环境、10000 更新的行走候选 |
| `workspace/beyondmimic/profiles/tracking_robust_4096.json` | 4096 环境、30000 更新的完整状态动作模仿候选 |
| `workspace/beyondmimic/profiles/tracking_no_state_estimation_robust_4096.json` | 4096 环境、独立观测契约的无状态估计候选 |
| `scripts/15_train_robust.sh` | 启动新的行走实验 |
| `scripts/16_train_tracking_robust.sh` | 启动新的动作模仿实验 |
| `scripts/tools/compare_policies.py` | 用相同协议、随机种子、环境数和时长比较多个策略 |

JSON 不支持注释，因此新 profile 用 `_notes` 保存中文解释；该字段不作为 PPO 参数传入。它仍属于 profile 文件，编辑它也会改变 profile 哈希，已有实验续训时应保留原文件。

配置顺序为：固定版本官方任务副本 → 确定命令行或续训继承的环境数/种子 → profile 的 `agent_overrides` → 显式环境配方 → 本次更新预算。推理时再应用独立评估协议。环境配方使用已经确定的采样长度构造课程阶段，生效环境与 agent 随训练保存为 YAML。

## 4. 保留的 PPO 公共基线及原因

| 参数 | 新配置 | 原因与注意事项 |
| --- | --- | --- |
| Actor / Critic | 512 → 256 → 128，ELU | 与本地参考和公开实现规模一致；不无依据增加网络开销 |
| 观测归一化 | Actor、Critic 均启用 | 当前 99/111 维输入包含不同尺度物理量，保留 mjlab 的归一化契约 |
| 每环境采样长度 | 24 | 4096 环境时一轮 98304 样本；4 个 minibatch 各 24576 样本 |
| minibatches / epochs | 4 / 5 | 每轮约 20 次 minibatch 优化；不是 20 次环境采样 |
| 初始学习率 / schedule | 1e-3 / adaptive | 按 KL 调节；不能将初始值理解为全程固定值 |
| desired_kl / clip_param | 0.01 / 0.2 | 保留公开 PPO 基线的更新幅度约束 |
| gamma / lambda | 0.99 / 0.95 | 控制周期仍为 0.02 s，折扣的时间含义没有被频率修改破坏 |
| 价值损失 | 系数 1.0，启用 clipped value loss | 保留原 Critic 优化方案 |
| 梯度裁剪 | max_grad_norm=1.0 | 保留原优化约束 |
| 优势归一化 | 整个 rollout 归一化 | `normalize_advantage_per_mini_batch=false`，与当前原生路径一致 |
| optimizer | Adam | 不将别的优化器的学习率和权重衰减直接搬来 |
| entropy | 行走 0.008；跟踪 0.005 | 分别来自本地 robot_lab 与 whole_body_tracking 的候选设置 |

新 profile 还采用 RSL-RL 原生 `std_type=log`：优化 log_std 后得到动作标准差。这是一项参数化对照选择，不是修复现有 scalar 的已知漏洞；RSL-RL 5.4.2 的两种参数化均有标准差边界处理。改变参数化会改变 checkpoint 参数名称，必须另起实验。

当前仍未启用未经本机验证的 AMP 混合精度、RNN、对称增强、off-policy 或多 GPU。4096 已在 AMP 和两种 tracking 任务完成短时容量测试，但这不是收敛、长期温度或多 GPU 验证。

## 5. 行走候选的课程与约束

新配方 `velocity_robust_v1` 保留物理步 0.005 s、decimation=4、策略周期 0.02 s、原 PD、动作尺度、关节顺序和 99/111 维观测。

### 5.1 分阶段速度命令

| 阶段起始 PPO 更新数 | 前后速度 m/s | 横向速度 m/s | 偏航角速度 rad/s |
| --- | --- | --- | --- |
| 0 | [-0.5, 1.0] | [-0.25, 0.25] | [-0.5, 0.5] |
| 1500 | [-1.0, 1.5] | [-0.5, 0.5] | [-0.7, 0.7] |
| 4000 | [-1.5, 2.0] | [-1.0, 1.0] | [-0.7, 0.7] |

该时间表是针对本机行走候选的工程设计，不是论文证明的最优阈值。先限制初期横移和倒走难度，再逐步覆盖原官方 play 的主要命令范围。

课程复用 mjlab 官方 `commands_vel`，按 `common_step_counter` 判断阶段。每轮 24 步时，阶段控制步为 0、36000、96000，不再乘并行环境数。新预算 10000 更新使后续阶段有训练机会；原来 3000 更新的观察预算无法覆盖官方 5000/10000 更新附近的后续课程。

这是按控制步推进的时间表，没有实现“达到成功率才升级”的性能门控。续训由官方 runner 恢复公共步计数，新配方在加载后 reset 环境，使第一次采样就使用对应阶段。修改 rollout 长度会改变阶段的控制步数与训练契约，不能无记录地续训。

play 使用最终阶段范围，并保留官方 play 的噪声/推力处理；固定速度评估在此之后覆盖命令，因此基线与候选可用相同物理速度比较。

### 5.2 三条新增代价曲线

| 名称 | 权重 | 意义与迁移细节 |
| --- | --- | --- |
| `Episode_Reward/failure_penalty` | -200 | 仅惩罚失败 terminated，排除正常 time_out；在当前 dt=0.02 下失败那一步约贡献 -4 |
| `Episode_Reward/leg_torque_l2` | -2e-6 | 约束髋/膝驱动器的实际 actuator_force 平方和；选择 actuator_names |
| `Episode_Reward/leg_acc_l2` | -1e-7 | 约束髋/膝关节加速度平方和；选择 joint_names |

三个系数参考本地 robot_lab G1 配置，但 PhysX 与 MuJoCo 的驱动和加速度分布不同，因此它们是需消融验证的起点。目标是减少靠失败结束回合的行为、过大下肢力矩和加速度，不保证所有系数都改善最终指标。若压制运动或跟踪退化，另建实验调整，不修改已训练 profile。

力矩平方是驱动努力度的代理代价，不等同于真实电池功耗或累计电能；不能仅凭这条奖励变小就宣称节能。

原有 14 项奖励保留。因此该候选通常比基线多 3 条奖励曲线；旧文档中的 41 条对应旧基线，不应当作新任务的固定曲线数量。新旧总奖励的定义不同，不能用它们的绝对数值直接排名。

## 6. 动作模仿与无状态估计候选

两个新 tracking profile 保留相应的官方观测契约、奖励、物理参数和控制频率；训练使用 `adaptive` 动作采样，回放使用 `start`。

自适应采样按失败片段增加训练机会，原有均匀分量保留，避免只记住少数困难帧。这里复用 mjlab 实现及其默认 adaptive 参数，不把速度任务的命令课程或下肢代价强加给舞蹈。

预算设为 30000 更新、每 500 更新保存，与本地 whole_body_tracking 和公开 tracking 配置对齐。相对每 100 更新保存，减少周期性模型落盘频率；最后一次模型仍由 runner 保存。预算不是收敛承诺，动作是否动力学可行仍需转换报告和回放。

`tracking_no_state_estimation_robust` 继续去掉指定状态估计观测。它有自己的任务 ID、profile 和 checkpoint，不能拿完整状态模型直接续训。两类模型也不在比较工具中当作完全相同任务混用。

## 7. 运行步骤

### 7.1 行走：新候选与旧基线分别训练

```bash
# 先检查新配方的仿真；不更新网络
bash g1.sh self-check --profile velocity_robust_4096

# 新行走候选：默认 4096 环境、10000 更新
bash scripts/15_train_robust.sh --seed 42

# 旧基线仍可从零训练，原 profile 不变
bash scripts/02_train.sh --seed 42
```

如果比较采样效率，为两者指定相同更新数和并行数；如果比较训练时间，在相同硬件负载下使用相同训练时间预算，并记录达到同一评估目标所需的时间。增加更新预算本身不代表算法更快。

### 7.2 动作模仿

```bash
# gym_rl 的 CSV 只在本地，未上传 Git；需要原始资料目录
bash scripts/10_import_motions.sh

# 完整状态版本
bash scripts/16_train_tracking_robust.sh --seed 42

# 无状态估计版本，另起实验
bash scripts/16_train_tracking_robust.sh \
  --profile tracking_no_state_estimation_robust_4096 --seed 42
```

跟踪任务建议先用自己的 motion 和 profile 做小规模 self-check/benchmark，再决定是否增加到 256 以上；本次没有自动发起长时间舞蹈训练。

### 7.3 续训与导出

```bash
# 默认继承原运行的 profile、动作、并行数和种子
bash scripts/03_resume.sh --checkpoint /实际运行目录/model_N.pt --iterations 1000

# 显式覆盖并行数/种子仍可用；这会改变采样批量/随机轨迹
bash scripts/03_resume.sh --checkpoint /实际运行目录/model_N.pt --envs 1024 --seed 7

bash g1.sh export --checkpoint /实际运行目录/model_N.pt
```

03 脚本不会把旧模型强制改为 4096。续训在没有显式参数时继承清单中的环境数；`G1_ENV_COUNT` 或末尾 `--envs` 可有意覆盖。只有从零训练快捷脚本默认使用新的 4096 profile。

新清单保存 `recipe`、`recipe_sha256`、`effective_agent_sha256`、`rollout_steps`、`samples_per_update` 和 `minibatch_size`。新配方代码或生效学习参数改变后拒绝续训；旧清单没有 recipe 字段时仍兼容。导出和仿真部署也走同一配置构造与契约检查，避免只在训练时应用配方。

## 8. 用相同协议决定是否保留

```bash
bash g1.sh --python scripts/tools/compare_policies.py \
  --checkpoints /基线/model_N.pt /候选/model_M.pt \
  --envs 16 --seconds 60 --seed 42
```

工具串行加载策略。速度任务固定测试前进 0.5 m/s、前进 1.0 m/s、横移 0.3 m/s、转向 0.5 rad/s；固定命令会关闭随机站立、航向等分支。tracking 对同一个动作使用相同种子、时长和环境数。不同任务或不同参考动作拒绝混成一组。

只检查某个速度协议时可加 `--protocols forward_0.5`；tracking 不接受这组选项。单次评估也可以通过 `--evaluation-seed 42` 显式指定种子，而不改变训练 profile。

报告保存在 `outputs/evaluations/comparison_*.json`，每个协议完成后写入一次，主要比较：

- 失败事件数、发生过失败的环境数、固定窗口无失败比例。
- 平面速度/偏航 RMSE；跟踪任务看关节角 RMSE 和对齐后的身体位置误差。
- 用时、吞吐和达到相同质量目标所需的样本量；资源余量见各训练运行的 resources.json。

此工具没有根据训练总奖励自动宣布优胜者，也不把某个实验的 60 秒无失败当作任意工况保证。正式结论建议至少 3 个训练种子，分别记录相同协议的均值与波动。

消融顺序可用旧 `velocity_flat` → 旧 `velocity_gym_ppo`（只改 entropy）→ 新 `velocity_robust`（课程、参数化和代价组合）。这只能先判断组合是否有效；要归因某一个改动，需再建立只改变该因素的新 profile。当前预算与未完成的长训不能被写成“已经优于基线”。

## 9. 验证范围

配置与单元测试检查不等于收敛结果。新增测试覆盖字典参数覆盖、类型/非有限值检查、采样整除、课程公共步阈值、train/play 采样差异、两种跟踪观测契约、续训默认值与配方哈希保护。

GPU 小规模 self-check/PPO 短测的实际结果另记录在 `docs/validation.md`。只有实际执行成功的项目才记为通过；完整动作质量、长时间训练收益和真机能力仍以对应实验结果为准。
